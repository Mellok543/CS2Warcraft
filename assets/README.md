# CS2Warcraft visual assets

`assets/addon/` mirrors the **content root** of the Warcraft UI Workshop addon
(`cs2warcraft_ui`). It contains ModelDoc sources for the ability models the
server spawns (`src/Warcraft.Abilities/Game/WarcraftModels.cs`):

| Model | Used by | Source |
|---|---|---|
| `models/warcraft/totems/totem_healing` | `healing_totem` | Meshy text-to-3D |
| `models/warcraft/totems/totem_flame` | `flame_totem` | Meshy |
| `models/warcraft/totems/totem_frost` | `frost_totem` | Meshy |
| `models/warcraft/totems/totem_war` | `war_totem` | Meshy |
| `models/warcraft/totems/totem_shield` | `shield_totem` | Meshy |
| `models/warcraft/totems/turret` | `turret_totem` (turns towards its target) | Meshy |
| `models/warcraft/effects/entangle_roots` | `entangle` (at the rooted target) | Meshy |
| `models/warcraft/effects/aura_ring` | every aura (tinted per aura, follows the owner) | generated |
| `models/warcraft/effects/shield_bubble` | `divine_shield` (follows the caster) | generated |

Totems are 64 units tall, the turret 56, the roots ring 72 units wide. Aura ring and shield
bubble use a translucent, self-illuminated `csgo_complex` material and are
tinted through the entity render color.

## Cosmetics (not wired to gameplay yet)

`models/warcraft/cosmetics/` — Meshy models ready to attach later. Origin is
the bottom centre of each model; attachment points and offsets are decided when
they get used. Trend picks are marked with *.

| Group | Models | Size |
|---|---|---|
| `hats` | wizard, viking, crown, cat_headset*, mushroom* | 16 units wide |
| `backpacks` | loot_sack, jetpack, quiver, mimic, capybara* | 24 units longest side |
| `pets` | dragon, owl, capybara*, axolotl*, cowboy_frog* | 16 units longest side |
| `masks` | kitsune, oni, cyber*, plague, orc | 11 units wide |

`mask_cyber`, `mask_plague` and `mask_orc` came out as full helmets. The
mushroom hat's stem is cut off by `CLIP_BELOW` in `prepare_models.py`.

## Particles

`particles/warcraft/*.vpcf` is generated by `assets/tools/make_particles.py`
(do not edit by hand). Archetypes × colours:

| Archetype | Use |
|---|---|
| `burst_*` | one-shot sparkle explosion (heals, hits, casts) |
| `nova_*` | shockwave and dust racing along the ground (stomp, repulse, battle cry) |
| `column_*` | pillar of light (smite, resurrect, reincarnation, level up) |
| `line_*` | ray from the entity to control point 1 (lightning, drain, tracer) |
| `radius_*` | loop, circle whose radius is control point 1's X (totem areas) |
| `motes_*` | loop, motes rising around the feet (auras, totems) |
| `body_*` | loop, particles around a player (poison, stun, rage, shields) |
| `sparks_*`, `smoke_*`, `flash_*` | one-shot impacts, puffs, glows |
| `flames_ring`, `flames_brazier`, `flames_rage`, `snow` | immolation, flame totem bowl, rage, frost totem |

Colours: heal, fire, frost, holy, war, storm, blood, poison, arcane, shadow,
nature (`FxColor` in `src/Warcraft.Abilities/Game/WarcraftParticles.cs`).
Operators and field names follow Valve's CS2 particles; the generator only uses
Valve textures, so the addon adds no particle textures. After changing the
generator, run it, rebuild the addon and keep `AddonAssetTests` green (every
generated file must be registered in `WarcraftParticles.All`).

## Build and publish

```powershell
powershell -ExecutionPolicy Bypass -File .\src\Warcraft.Menu\hud\build.ps1 -Cs2 "E:\Steam\steamapps\common\Counter-Strike Global Offensive"
```

The script copies `assets/addon/*` into `content/csgo_addons/cs2warcraft_ui/`,
compiles the Panorama HUD, every `models/warcraft/**/*.vmdl` and
`particles/warcraft/*.vpcf`, then fails if any compiled file is missing. Upload the compiled addon from the Workshop Tools
as usual (see `src/Warcraft.Menu/hud/PUBLISH.md`).

Server and clients must both mount the addon (MultiAddonManager). If the
server runs without it, set `configs/warcraft/visuals.json` → `"models": false`
and `"particles": false`: totems then fall back to beam pillars and rings, rays
to beams, and aura rings, shields and particles are not drawn.

## Regenerating models

```bash
# 1. Generate (≈30 Meshy credits per model; resumable via meshy_state.json)
MESHY_API_KEY=... python assets/tools/meshy_generate.py <work_dir>

# 2. Inspect: textured front/side preview PNG for each OBJ
python assets/tools/preview_obj.py <work_dir>/totem_war/model.obj <work_dir>/totem_war/texture.png preview.png

# 3. Normalize into assets/addon (scale, ground, Y-up, 1024px textures, vmdl/vmat)
python assets/tools/prepare_models.py <work_dir>
```

Never commit the API key. `prepare_models.py` keeps OBJ Y-up on purpose:
ModelDoc imports OBJ as engine `(x, y, z) = obj (z, x, y)` at scale 1
(verified by compiling a test box and reading its bounds from the `.vmdl_c`).
Models whose generated shape stands although it must lie on the ground are
listed in `LAY_FLAT`.
